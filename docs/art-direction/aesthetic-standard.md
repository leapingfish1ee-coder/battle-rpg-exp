# Battle RPG EXP 美学与画面质量规范

Status: Active  
Scope: 所有玩家可见的世界、角色、UI、特效、动画、资源与后处理  
Authority: 本文是项目视觉方向的长期真值；任何新增或重做画面都必须遵循本文，除非后续文档显式取代本规范。

## 1. 核心定义

项目主体美学定义为：**日式西幻，典雅庄重，以高精度渲染和克制的后处理建立精致、沉静、可信的幻想质感。**

“日式西幻”指日本角色扮演游戏常见的清晰叙事层级、精炼角色设计、仪式感界面与理想化幻想世界，与欧洲中世纪至文艺复兴时期的建筑、兵器、服装、纹章和材料语言结合；它不等于廉价动漫化，也不等于写实欧美黑暗奇幻。

“典雅庄重”要求画面以秩序、比例、留白、材质、光影和节制建立高级感，不依赖高饱和、过密装饰、强烈噪点或夸张动效制造刺激。

“高精度”指最终视觉在目标设备能力允许范围内优先保证轮廓、文字、材质边缘、光照过渡和特效细节的稳定性，并通过分辨率、采样、资源精度和后处理链共同实现，而不是简单提高纹理尺寸或 DPR。

## 2. 五项视觉支柱

1. **典雅 Elegance**：比例克制、装饰有来源、颜色有层级、复杂度集中在焦点区域，任何元素都不得为了“华丽”而无目的堆砌。
2. **庄重 Solemnity**：构图、字体、建筑、纹章、金属和仪式性元素传达历史感与秩序感，避免轻浮、玩具化和廉价手游化表达。
3. **清晰 Clarity**：角色、交互对象、菜单层级、战斗反馈必须在复杂背景上保持一眼可读，视觉质感不得牺牲玩法信息。
4. **精工 Craft**：边缘、描边、材质、阴影、粒子、动画和转场需要体现一致的制作精度，禁止明显的占位图形、粗糙渐变和不统一的默认样式混入正式画面。
5. **克制 Restraint**：高光、Bloom、粒子、镜头震动、色差、辉光和屏幕滤镜都必须服务于叙事或交互层级，效果强度默认取可感知但不抢夺主体的最低有效值。

## 3. 风格边界

### 3.1 应当接近

- JRPG 式的清晰角色剪影、精炼服装层次、英雄主义和仪式感。
- 罗曼式、哥特式、早期文艺复兴与幻想化王国建筑语言。
- 石材、深色木材、锻铁、黄铜、旧金、皮革、羊皮纸、玻璃、天鹅绒等可识别材料。
- 古典纹章、宗教式拱券、骑士装备、行会标识、星象与魔法几何等结构化装饰。
- 低至中等饱和度的大面积基色，配合少量高价值暖色或魔法色作为焦点。

### 3.2 明确避免

- Q 版、Chibi、玩具比例、幼态大头身作为项目主视觉。
- 霓虹赛博、现代扁平科技 UI、玻璃拟态、强塑料质感和无来源的科幻发光线。
- 欧美 grimdark 式全局脏污、过度血腥、极低曝光和不可读的黑灰画面。
- 大面积纯黑、纯白、满饱和 RGB 原色、彩虹渐变或高频颜色竞争。
- 无节制 Bloom、全屏模糊、持续色差、重颗粒、过强 vignette、镜头污渍和伪电影黑边。
- 将所有边框、按钮、标题同时做成金色高亮；金色只用于身份、等级、选中、稀有度或仪式性重点。

## 4. 构图与空间

- 主要场景采用稳定水平线、明确前中后景和单一主焦点，默认保持可读的空间纵深，而不是把对象平均铺满画面。
- 宫殿、教堂、行会、城门等庄严场所优先使用轴线、近对称或受控非对称构图，强调建筑重量、尺度和秩序。
- 角色与交互物必须通过明度、色温、轮廓、局部光源或空间留白从背景中分离，不依赖永久描边解决所有可读性问题。
- 前景可使用旗帜、栏杆、植被、柱体或雾层建立景深，但遮挡不得破坏交互目标识别。
- UI 与场景必须共享视觉重心；HUD 不得把画面切割成多个互相竞争的高对比区域。

## 5. 色彩与明度

### 5.1 基础色域

默认视觉基底使用深海军蓝、炭灰、石灰、象牙白、旧金、黄铜、暗红木与低饱和自然色，魔法色作为场景或系统语义的局部变量而不是全局底色。

### 5.2 层级规则

- 背景：低对比、低至中饱和，保留材质变化但不抢焦点。
- 可交互主体：中高局部对比，允许适度冷暖分离。
- 当前选择/关键动作：使用旧金、象牙白或语义色形成最高局部对比。
- 危险、错误和生命危机：红色仅用于明确系统语义，不作为常驻装饰色。
- 稀有魔法或超自然事件：允许更高饱和度，但同屏原则上只保留一个主要魔法色族。

### 5.3 色彩纪律

- 单个画面建议保持 1 个主色族、1 个辅色族和 1 个强调色族。
- 同一 UI 层级内不使用多个等强度强调色竞争注意力。
- 黑位必须保留细节，不通过压死暗部制造“高级感”。
- 高光必须保留材质层次，不允许大面积剪切成纯白。

## 6. 材质与表面语言

- 金属必须区分铁、钢、黄铜、旧金等材质倾向，至少通过明度、色温、高光宽度和边缘磨损差异体现，而不是统一灰色描边。
- 石材强调重量、粗糙度和年代感，但污渍、裂纹与苔藓只做局部叙事，不覆盖所有表面。
- 木材使用低饱和暖色与方向性纹理，禁止橙色塑料感。
- 织物、皮革和羊皮纸以柔和漫反射和边缘变化表现，不使用玻璃般高光。
- 发光魔法必须有明确发光源、衰减范围和对周边颜色的影响，禁止独立悬浮的无环境响应辉光。

## 7. 角色与服装

- 主体角色采用成熟、修长、可信的人体比例，允许 JRPG 式理想化，但禁止默认 Q 版比例。
- 服装轮廓先表达职业与身份，再增加装饰；骑士、法师、祭司、商人、贵族和市民应能仅凭剪影与材料分辨。
- 金属护甲、布料、皮革和饰品的层级必须可读，避免所有区域拥有相同边缘强度和高光。
- 发色、瞳色和魔法色可以理想化，但整体饱和度必须受场景色彩体系约束。
- 面部表情以克制和清晰为优先，不用过度夸张的动漫符号替代表演。

## 8. 建筑与环境

- 建筑主体使用石、木、金属与玻璃构成可理解的承重关系，即使幻想化也应保持结构可信度。
- 城镇场景应通过屋顶线、塔楼、拱券、旗帜、钟楼、城墙和远景地标建立可记忆轮廓。
- 室内优先使用壁炉、烛台、彩窗、吊灯、窗光和局部魔法光作为有来源照明。
- 环境装饰必须服务于地区、阶级、宗教、行业或历史信息，禁止复制粘贴无意义的“中世纪杂物”。
- 天气、雾、尘埃和云层用于建立层次与气候感，强度不得遮挡玩法信息。

## 9. UI 与排版

- UI 视觉基调为深色矿物/木材基底、象牙文字、旧金结构线和少量纹章装饰，强调“典籍、行会、公会文书、王国仪式”而不是现代软件面板。
- 大标题允许使用具有古典骨架的 Display Serif；正文与 CJK 必须优先保证屏幕可读性，并提供稳定的字体回退链。
- 文本信息层级通过字号、字重、留白、明度和位置建立，禁止依赖过量阴影、描边或全大写制造层级。
- 边框优先使用细线、双线、角饰、压纹和局部金属节点，禁止每个容器都使用厚重金框。
- 按钮 hover/selected/pressed 的形状尺寸必须稳定，状态变化只允许设计明确的颜色、明度、纹理、描边或轻微受控位移，不得出现累计 scale 或 bounds 漂移。
- HUD 永远优先于装饰可读性，战斗关键信息在后处理后仍必须保持清晰。

## 10. 光照与氛围

- 每个场景必须定义主光方向、主色温、环境光倾向和至少一个视觉焦点，禁止没有光源逻辑的均匀提亮。
- 日间优先保持空气透视和自然天空色反射；夜间使用月光、火光、灯光和魔法光形成有限光池，而不是整体压黑。
- 暖色光用于庇护、文明、火焰、室内与仪式；冷色光用于月夜、远景、神秘和危险空间，但不作为绝对语义规则。
- 阴影用于建立形体和层级，默认保持可读的半影与环境填充，避免大片纯黑硬切。
- 雾与体积感以深度分层、透明度和低频变化实现，禁止覆盖 UI 或近景交互对象。

## 11. 高精度渲染基线

### 11.1 分辨率策略

- 渲染分辨率由 `DeviceProfile` 控制，不直接等于设备 DPR。
- High：内部渲染 scale 建议为 CSS 像素的 `1.5–2.0×`，上限按 GPU 与显存 profiling 决定。
- Medium：建议 `1.25–1.5×`。
- Low：建议 `1.0×`，优先保证稳定帧时间和 UI 清晰度。
- UI 文本、细线和图标必须在所有质量等级保持可读，动态降级优先牺牲粒子、环境特效和后处理精度，而不是先降低文字质量。

### 11.2 资源精度

- 角色、UI 核心图标和近景装饰按照最高目标显示尺寸准备足够采样余量，禁止依赖浏览器放大低分辨率源图。
- Texture Atlas 必须保留 padding/extrusion，避免缩放和 mip sampling 产生相邻纹理污染。
- 需要缩放的几何装饰优先使用可安全九宫格、矢量化或程序绘制方案。
- 像素风 nearest-neighbor 不是本项目默认采样策略；正式主视觉默认追求平滑、细腻和稳定边缘。

### 11.3 精度原则

- RenderTexture、滤镜输入输出和中间缓冲区不得无理由长期使用低于场景所需的分辨率。
- 半透明层、渐变、雾与阴影需要避免明显 banding；必要时使用低强度 dither/grain 打散量化条带。
- 小字号文字、1px 结构线与细边框必须在常见 viewport 上进行实机截图检查，禁止只凭设计稿确认。

## 12. 后处理标准

后处理不是独立风格，而是统一场景材质、光照和色彩的最后阶段；默认链路按以下顺序设计，具体实现可以根据 PixiJS 与设备能力合并 pass：

```text
scene render
→ exposure / tone shaping
→ color grading
→ selective bloom / glow
→ atmospheric integration
→ subtle vignette
→ dither / very subtle film grain
→ UI-safe composite
```

### 12.1 Tone 与 Color Grade

- 全项目需要稳定的黑位、白点和中间调关系，场景差异通过受控曝光和色彩分级实现。
- Color grade 应强化旧金、石材、天空、火光和肤色的协调，不得把所有场景套成同一个重滤镜。
- 禁止通过极端对比、青橙滤镜或整体去饱和模拟电影感。

### 12.2 Bloom / Glow

- Bloom 仅作用于足够明亮的发光源、高等级魔法、金属强反射或仪式性焦点。
- 普通文字、普通边框和常规按钮不得常驻 Bloom。
- Bloom 必须保留光源核心，不得把高光扩散成失焦白团。

### 12.3 Vignette

- Vignette 只用于轻微收束视线，默认强度应在玩家不主动注意时仍有效。
- 菜单、HUD 密集场景和小屏设备应减弱或关闭 vignette，避免降低边缘 UI 可读性。

### 12.4 Grain / Dither

- 允许极低强度 grain/dither 用于减少渐变 banding 和统一数字画面质感。
- Grain 不得成为可见噪点层，不得覆盖小字号文字和细线 UI。

### 12.5 明确限制

- Chromatic aberration 默认禁用，仅允许在瞬时传送、精神异常、强魔法冲击等明确叙事事件中短时使用。
- 全屏 blur 不得作为常驻质感手段；景深效果只能在非交互焦点明确、且不会损伤 UI/目标识别时使用。
- Screen shake、flash、distortion 和 glitch 必须受可访问性与强度上限控制。

## 13. 质量等级与降级顺序

High 目标是完整高精度渲染、完整但克制的后处理、较高粒子密度与环境层次；Medium 保留核心 color grade、必要 bloom、基础 atmosphere 与完整 UI 精度；Low 保留色彩统一和 UI 清晰度，允许关闭高成本 bloom、多层雾、粒子、额外 RenderTexture pass 和高频装饰动画。

推荐降级顺序：

```text
非关键粒子
→ 远景装饰动画
→ 多层 atmosphere
→ bloom sample / radius
→ 次要 post-process pass
→ world render scale
```

UI 文本清晰度、交互状态、主角色轮廓和关键战斗反馈不属于优先降级项。

## 14. 动画与特效

- 常规 UI 动画使用 120–240ms 的短缓动表达响应，庄重界面的面板转场可延长到约 300–450ms，但不得拖慢操作。
- 角色待机、布料、旗帜、火焰和环境粒子使用低振幅持续运动建立生命感，避免所有元素同时高频摆动。
- 战斗命中必须先保证时序、轮廓和方向可读，再叠加粒子、闪光和屏幕反馈。
- 稀有技能允许短时突破平时的饱和度和亮度上限，但结束后必须迅速回归基础色彩体系。

## 15. 视觉质量验收

任何新增或显著修改玩家可见内容的 PR 必须至少回答以下问题：

1. 是否符合“日式西幻、典雅庄重”的主体语言，而不是临时采用另一套流行视觉风格。
2. 主焦点、交互对象和信息层级是否在 3 秒内可辨认。
3. 材质、光源和装饰是否有明确来源与功能。
4. 是否存在无必要的高饱和、高辉光、高噪声或高频动画。
5. High/Medium/Low 是否有明确降级行为，且低质量档仍保持 UI 与玩法可读性。
6. 后处理开启后是否仍保留文字、边缘和高光细节。
7. 标准与 compact viewport 是否都保持构图、字号、边框和交互状态稳定。
8. 同一语义状态重复渲染或重复交互后是否保持几何和像素稳定，不产生累计漂移。

## 16. 自动化与评审要求

- 可量化的视觉约束应逐步进入 Playwright 视觉回归、组件测试、性能采样或 lint，而不是永久依赖人工记忆。
- 关键场景必须建立固定 viewport、固定时间、固定随机源和固定 fixture 的视觉 baseline。
- 后处理参数、渲染 scale、质量等级和效果开关必须由集中配置管理，禁止散落在 View 内形成不可追踪的局部风格。
- 新增全屏 filter、RenderTexture 链或明显增加 GPU 成本的效果必须提供 before/after 截图和至少一种性能依据。
- 视觉评审发现“风格方向不一致”时，不以“功能正确”作为合并理由；功能正确与美学一致性是两个独立门槛。

## 17. 设计决策优先级

当视觉质量、性能和实现复杂度冲突时，按以下优先级决策：

```text
玩法与文字可读性
> 帧时间稳定性
> 主体美学一致性
> 关键角色/场景精度
> 后处理丰富度
> 非关键装饰数量
```

该优先级意味着“高精度”不是无限增加 GPU 成本，而是在稳定性能预算内，把精度优先分配给最影响美学与可读性的部分。
